# Implementation and research decisions

## Desktop background fill

The [OBS aspect-ratio guide](https://obsproject.com/kb/aspect-ratio-guide) recommends filling unused canvas space rather than stretching a source (distortion) or enlarging it (content loss). StreamApp preserves the sharp aspect-fit desktop/window and composites a configurable background behind it. Settings → Scene → Background owns this section; the quick menu has no new controls. Existing settings retain Black.

- **Color:** opaque custom sRGB, quiet and inexpensive.
- **Image:** aspect-fill imported artwork behind the sharp source; transparency uses the selected fallback color. Images are oriented/downsampled to 2048 pixels and copied as PNGs into app-owned storage, so moving the original does not break a setup.
- **Blurred desktop:** a separate enlarged copy, quarter-resolution Gaussian blur, clamped before filtering and cropped afterward. Only the background is blurred. This is the recommended subtle fill; it can still reveal broad shapes/colors from the already-captured source.
- **Mirrored wallpaper:** takes one wallpaper-only screenshot from the selected display's rendered WallpaperAgent surface using [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(contentfilter:configuration:completionhandler:)). `NSWorkspace.desktopImageURL(for:)` returned the default beach image on this Mac, not its active mountain wallpaper, so file URLs and downloaded-asset guesses are not used. Window capture chooses the display containing the largest portion of the window; the snapshot is cropped to the window or Dock-fit region. Captured app content is never used for this mode. Identification requires one on-screen, negative-layer `com.apple.wallpaper.agent` window matching the display bounds. That window identity is an OS implementation detail, not a guaranteed wallpaper API; missing or ambiguous matches use the solid fallback.

Snapshots refresh on source changes, Space/display/wake notifications and wallpaper-store filesystem events (without parsing private settings). Unrelated settings retain the snapshot. Static backgrounds (Image and Mirrored wallpaper) are baked into one GPU-resident IOSurface per image/geometry/color change once the scene is settled, rather than re-decoding the image or reevaluating reflection filters every video frame; mid-transition frames draw the recipe directly so the cache does not churn. Animated wallpapers remain still snapshots between refresh events; continuous animation synchronization would require ongoing capture.

The Metal preview uses transaction-synchronized presentation so its drawable updates participate in the surrounding native UI composition. Following Apple's [`presentsWithTransaction`](https://developer.apple.com/documentation/quartzcore/cametallayer/presentswithtransaction) contract, it commits the command buffer, waits until scheduled, then calls `drawable.present()` rather than scheduling presentation on the command buffer. This addresses a possible compositing cause of corrupted native controls; the original corruption's root cause has not been isolated.

Implementation uses [Core Image's Gaussian blur, affine tiling and compositing filters](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Reference/CoreImageFilterReference/index.html). The reflected tile uses an explicit identity transform: the runtime CIAffineTile default scales by 0.4, which is not acceptable for edge continuity. Native pixel regression covers nonzero image/canvas origins and repeated reflection across wide bars. Static image loading and immediate thumbnail decoding run outside the compositor queue; changed paths clear stale images and stale completions cannot replace newer choices. The same FrameRenderer path feeds preview and encoded output. Camera/chat layering and Dock geometry remain unchanged.

## Product surface

StreamApp is an AppKit `NSStatusItem` + `NSPopover` hosting SwiftUI cards and a separate settings window. The scenes are **Desktop**, **Split**, **Full Camera** and **Away**, with independent chat rendering, chat side/width, webcam corner/size, device selection and live audio controls. Existing scene identifiers remain unchanged in saved settings; missing configuration fields decode with defaults rather than discarding older settings.

The Pace Bar reference was `../pace-bar/Sources/CodexBar/`: `UsageMenuCardLayout.swift` supplies the compact 20pt horizontal-padding/section rhythm; `StatusItemController+MenuPresentation.swift` illustrates native SwiftUI hosting and measured layouts; `StatusItemController+MenuTracking.swift` documents why frequent meter updates should not rebuild a synchronously tracking NSMenu. StreamApp uses a popover and one stable status item. Meters sample at 5 Hz; output health samples at 1 Hz. Levels publish through a separate `AudioMeters` object observed only by the mixer rows, so 5 Hz meter updates do not invalidate the rest of the popover or Settings; engine and configuration properties publish only on change. Preview presentation runs independently of SwiftUI updates.

Popover placement is owned by AppKit: one retained hosting controller uses `sizingOptions = .preferredContentSize`, so the popover takes its SwiftUI content height (no scroll view) and grows or shrinks only when the video preview is toggled. There is no `popoverDidShow` frame correction; that previous correction visibly moved the already-open window. Animation is disabled for immediate menu-like presentation (Apple documents `animates` as a hint, not a guarantee). Dictation's `src-tauri/src/lib.rs` attaches its Tauri menu with `show_menu_on_left_click(true)`; Pace Bar's `StatusItemController.swift` attaches `NSMenu` to the status item. Neither is evidence for manually moving an already-shown popover. StreamApp retains NSPopover for live sliders/meters, using [AppKit anchoring](https://developer.apple.com/documentation/appkit/nspopover/show(relativeto:of:preferrededge:)) and [animation policy](https://developer.apple.com/documentation/appkit/nspopover/animates).

Source/device/output settings lock during a session. Scene selection, chat geometry, webcam enable/position, gains and mutes remain live. Start does not silently grant permissions or substitute a synthetic input for a missing real source. Broadcasting requires explicit confirmation. The whole menu fits one panel: scene/preview header, a five-button control strip (Webcam, Punch in, Chat, Annotate, Clear), one row per audio source plus a thin Mix meter, one warning line, the session row, and Settings/Quit.

Settings panes share `SettingRow` (label, control, and a reset arrow beside the label that appears only when the value differs from its default, so controls never shift) and `SliderValue` (fixed-width slider and readout). Rows that don't apply are hidden rather than disabled; hidden settings still take effect. List refreshes are a **Refresh List** item inside the source and app-audio menus, not separate buttons, and the webcam Position menu ends with **Arrange on Desktop…**. The Scene pane reuses the menu's `SceneStage`, with the scene list beside the scene card instead of below it.

The pinned menu output controls use one **Record / Stream / Both** selector, also available in Output settings, and a single **Start / Stop** button. The selector maps atomically to recording/streaming flags; saved server/key/test settings do not choose the mode. Record never reads the key or validates/uses the server and ignores a retained bandwidth-test setting. Selecting Stream/Both or pressing Start with invalid streaming configuration opens a focused connection setup using the existing RTMP/RTMPS validation and Keychain storage. Completing setup does not start output or mark general onboarding complete. Broadcast confirmation still precedes streaming. Idle mode captions are omitted; the non-live bandwidth-test indicator remains. Mode selection is unavailable during a session. Legacy settings with both outputs disabled normalize to local recording.

Capture access follows macOS convention: access is requested in context when a source is turned on (webcam/microphone/app-audio switches, onboarding **Allow…**), never automatically. `.notDetermined` shows the system prompt and enables the source only if granted; a fresh **Don't Allow** is not followed by System Settings. Denied access shows an alert offering **Open System Settings**; restricted access explains itself. Controls are not disabled for missing access. Screen Recording exposes only preflight/request, so a stored flag distinguishes never-asked from denied. `captureAccessIssues` lists only permissions the current configuration needs; the popover shows one compact banner and Settings shows a notice beside the affected section. Synthetic demos do not require permissions. Idle preview preflights only its configured inputs and waits without opening devices when permission is missing. Explicit recording preflights still enforce authorization.

The camera uses `systemPreferredCamera` for **Automatic** (Continuity Camera and the user's system choice), refreshes camera/microphone lists on device connect/disconnect, delivers native 4:2:0 YUV instead of BGRA when available (Core Image composites it directly), and caps the device at 30 fps to match the renderer. Losing the camera or a camera runtime error never ends a recording or broadcast and never changes the configuration: the frame clears, the renderer's `cameraReady` turns false (Full Camera shows the Away card, Split a chat-only column, Desktop no webcam), `cameraStatus` reports it, and the same device reconnecting — or any camera for Automatic — resumes capture. **Settings → Scene → Video effects** opens the system camera effects panel. macOS shows that panel only while the app has a camera open, so **Open…** appears only while `StudioEngine.cameraOpen` (session or preview camera). Otherwise the row offers **Turn On Preview**, which starts the ordinary program preview; the button never opens the camera by itself.

The application-defined popover closes on outside clicks and Escape. Status-item clicks are excluded from local/global dismissal monitors so the button's action toggles once rather than closing on mouse-down and reopening on mouse-up.

**Fit 16:9** restores the original `CFPreferences` write plus a targeted `SIGTERM` to the running `com.apple.dock` process. Size and temporary visibility are committed together before that restart, rather than showing a small Dock and resizing it in a second transition. This replaces the System Events implementation; no Automation entitlement or private CoreDock API is used. Handoff, recents, pinned items, animation and delay preferences are untouched. Apple’s [Dock management schema](https://github.com/apple/device-management/blob/release/mdm/profiles/com.apple.dock.yaml) specifies tile sizes 16…128.

The target comes from `SceneGeometry.desktop`: display height minus display width divided by the desktop slot's aspect ratio. Chat therefore requests a smaller Dock. An impossible target saturates at the smallest Dock. Bounded feedback uses pixel-size preferences; a one-second active-fit monitor follows changes to reserved height, Dock contents, displays and chat geometry. Size corrections restart Dock, while a saturated size is accepted without repeated restarts. Capture uses the measured region above Dock, preserving the menu bar and desktop width; the existing compositor aspect-fits that region into the scene. A positive reservation and an on-screen Dock surface on the selected display are required before publishing a crop.

Region changes publish through StudioModel and call `SCStream.updateConfiguration` on an already-running menu preview without restarting its camera or audio. Original, pending and applied sizes are journaled privately. Restore checks ownership and preserves external size changes, including recovery of interrupted normalized-control journals from the previous implementation. [Apple documents Handoff icons](https://support.apple.com/en-us/102426), including Notes, as transient Dock entries from nearby devices.

Fit journals original auto-hide and the pre-fit bottom reservation. Disable restores exact saved pixels and original hiding in one preference transaction/restart; a newer manually hidden state is never made visible on exit. A hidden Dock must return to its pre-fit bottom boundary (within one point) before the journal is removed. A persisted recovery phase prevents the active-fit monitor from enlarging Dock again after an interrupted or timed-out restore. A failed enable rolls back through the same path. Legacy size-only journals leave visibility untouched. StreamApp does not move other apps’ windows; [Apple’s visibleFrame API](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe) reports usable geometry, not a guarantee that existing windows reposition.

Twitch bandwidth tests use the documented `bandwidthtest=true` query only on recognized Twitch ingest hosts. Both test and live starts require confirmation. Twitch Inspector, not local FFmpeg progress, establishes remote delivery quality.

Dictation's `../dictation/docs/onboarding.md` supplied the Connect → Prepare → Try it structure, explicit permission recovery and optional real trial. StreamApp's trial copies settings and forces local recording with streaming disabled; live trial changes preserve that isolation. One task owns stop/finalization, including close during device startup. Onboarding completion is separate from the existing Codable settings schema.

Twitch uses the registered public client **StreamApp by btuckerc** with [Device Code OAuth](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/) and exactly `user:read:chat channel:read:stream_key`. No client secret or central backend is shipped. `TwitchSession` stores tokens atomically in Keychain, validates at startup and hourly, serializes single-use refresh rotation, and prevents cancelled requests from resurrecting an account. Twitch stream keys are fetched for the authenticated account immediately before confirmed output startup; local recording bypasses that request. Missing service choices default to Twitch; explicit Custom RTMP choices, stored keys and URLs are retained. Changing service clears stale validation feedback in both Settings and onboarding.

## Media path

```text
ScreenCaptureKit ─── latest slot / shield history ─┐
AVCapture camera ─── latest slot / shield history ┼─ Metal/CoreImage composition
Cached local WKWebView chat snapshot ──┘          │
                                      VT encoder pixel-buffer pool
                                                 │
                                      hardware H.264, no B-frames
                                                 │
                                      native timestamped FLV writer
                                                 │
Microphone + SCK audio → bounded native PCM mix → FFmpeg
                                                 ├─ hybrid-fragmented MP4 (default) or Matroska recording
                                                 └─ bounded FIFO RTMP/RTMPS, reconnect
```

- `CaptureEngine.swift` owns main-actor lifecycle, authorization preflights and explicit device ownership. Capture callbacks use separate queues and bounded latest slots; shielded sessions additionally retain app-owned input history for the fixed 0.5 s render-late pipeline described below.
- `FrameRenderer.swift` composes on its own serial queue. Immutable pooled frames are reused when inputs/configuration have not changed; the 30 Hz encoder clock continues. Full raw video never crosses a process pipe. `GPUPreview.swift` retains only the latest composed IOSurface for program preview, or the captured camera buffer for an opt-in webcam view. Metal/CoreImage scales it into the drawable without CPU readback or repeating scene composition. One GPU submission is allowed in flight; rendering never waits for the preview. Hidden/occluded/offscreen views pause and release the mailbox. Diagnostic PNG export is an explicit one-off, not a presentation path.
- CPU-backed images (chat snapshots, slates, static backgrounds) are uploaded to a GPU-resident IOSurface once per new image, not per frame: Core Image re-uploads a `CIImage(cgImage:)` on every render (≈2 ms CPU per 1080p frame measured, versus ≈0.8 ms for a resident buffer). The chat upload reuses a pool sized to the snapshot.
- `SceneTransition.swift` moves scene changes rather than fading them, using Material 3 motion tokens. Layout geometry (desktop, webcam, Split column) eases over 500 ms with emphasized cubic-bezier(0.2, 0, 0, 1); chat follows the same curve 60 ms later, so the column lands and then fills. Chat is never squeezed: `SceneGeometry.chat` always has the size of its target slot and, when chat is off, is parked just outside the frame (past the chat-side edge, or below the frame in Split), so turning it on or off slides it at full size; parked chat moving to another parking place jumps there unseen rather than crossing the frame, and the renderer then lets go of its last page. Privacy changes never animate: entering Away (or an unready Full Camera) snaps every layer to the target on the next frame with `away` = 1, and `awaySettle` then decays over 600 ms with emphasized-decelerate (0.05, 0.7, 0.1, 1), scaling the card from 103% about its centre. Leaving Away snaps the scene underneath to its target while the card still covers it fully, and lifts the card off the top over 350 ms with emphasized-accelerate (0.3, 0, 0.8, 0.15), with a 48 px shadow under its edge; a scene chosen during the lift moves on from what is visible. A disappearing webcam is removed on the next frame while the rest keeps moving. Camera-only geometry changes use 600 ms cubic-bezier(0.22, 0, 0.18, 1): a soft departure and gentle settle without overshoot. Each curve is inverted by bisection; settled frames bypass easing. Interruptions retarget from visible geometry, not a previous endpoint; completion settles to exact targets. The program ignores macOS Reduce Motion: it is footage for viewers, not this Mac's interface (the Settings diagram, which is interface, honours it). Full Camera retains sharp full-frame camera video; only the right chat panel plus a 48px kernel halo is cropped, downsampled to ¼ resolution, Gaussian-blurred on Metal and tinted. Text is composited afterward. There is no second encoder, full-frame blur or CPU blur path.
- The desktop webcam supports Wide (16:9), Square, and Circle frames. Core Image applies shape-aware alpha clipping and a quiet cached shadow while keeping camera pixels sharp. Settled Full Camera bypasses both. Two background-refraction prototypes—a narrow collar and a wider distorted bezel—still read as outlines in identical-source visual probes, so the unconvincing Glass option and its saved setting were removed rather than shipped.
- Scenes: **Desktop** (`desktopChat`), **Split** (`sideBySide`), **Full Camera** (`justChatting`) and **Away** (`away`); raw values are persisted, and an unknown saved scene falls back to Desktop instead of discarding the whole configuration. `SceneLayout.showsDesktop` (Desktop, Split) is the single gate for screen capture, the Desktop source requirement and annotations; punch-in, dragging, Arrange on Desktop and cursor avoidance stay Desktop-only because only there does the webcam float over the desktop. Desktop ↔ Split keeps the running `SCStream`. Entering a desktop scene is make-before-break: the engine starts the stream, then awaits `RenderInputs.waitForScreen(after:)`, which resolves once a screen frame newer than the mark is what the renderer would draw (after the privacy shield's selection) or after 45 render ticks; render ticks drive both, so there is no timer, and `closeScreenWaits` releases waiters when the inputs fail or their renderer finishes. Only then is the new layout committed. Leaving a desktop scene commits the layout first and then stops the stream, keeping its last frame for the outgoing transition. Live updates are serialized and `StudioModel.scheduleUpdate` coalesces them, so before coalescing it calls `CaptureEngine.request(_:)` on every change. That records the newest intent and configures the running renderer at once with `privacyMasked`, which applies `StudioConfiguration.hiding(as:)`: the webcam goes off, the layout becomes Away or loses the desktop, and the microphone is silenced, wherever the newest intent has them. Program audio gets the same mask at once through `MediaOutput.hide(as:)`: `AudioMixer` keeps the newest request and masks every configuration it applies with it, so Away silences the room from the next 20 ms block and an older update committing later cannot unmute it. Every commit of an earlier queued update goes through the same mask, so hiding never waits behind another switch, while showing more (or hearing the microphone again) waits for its own commit. Repeated requests that leave the mask unchanged do not reconfigure the renderer. `SceneLayout.usesCamera` (Split, Full Camera) marks scenes that need the webcam: `StudioModel.canSelectScene` is false while it is off, `selectScene` then beeps and explains instead of changing anything (it never turns the webcam on), and turning the webcam off, or decoding such a pairing, falls back by `SceneLayout.withoutCamera` (Split → Desktop, Full Camera → Away, so the desktop never appears unasked). Turning the webcam off in Full Camera sets the unsaved `awayCoversWebcam`, so `awaySilencesMicrophone` ignores **Mute microphone while away** for it; a relaunch (or decoding an older saved Full Camera without the webcam) starts as a chosen Away, which silences the room per its setting and says so in the menu. Turning the webcam back on never changes the scene, and choosing any scene clears the flag. The idle preview applies scene, webcam and chat changes in place (adding or removing only that source); a full rebuild keeps the last preview frame until the new renderer replaces it. `GPUPreview` stays transparent until its first frame, so the menu shows **Starting webcam…** behind Webcam only while the camera starts.
- `SceneGeometry` adds `sidebar` (Split's 600 px camera-and-chat column, parked just outside the chat-side edge elsewhere so it slides in), `away` (0–1 cover) and `awaySettle`. Split fits the desktop into the remaining area over the configured background, stacks the webcam card (frame aspect, 20 px gutters) over chat, turns the webcam into a full-height portrait card when chat is off (Circle stays round), and gives the whole frame back to the desktop when neither is on. `SceneGeometry.chatSize` is the chat slot for a configuration (384 × 1080 in the Desktop column by default, 560 × 705 under a wide Split webcam, 384 × 1032 in Full Camera); `Chat.resize(to:)` relays the page out at that size before the scene moves, and `FrameRenderer.composeChat` draws it 1:1, pinned to the slot's lower-left so the newest messages stay put. While the slot changes size the old page shows until the move is under way (`FrameRenderer.handover`) and the panel is wide enough for the new page's lines, whose 16 px side padding alone may still be cropped; the new page then replaces it in a single step (on the first moving frame when the panel narrows or keeps its width). No page is scaled or faded and the two layouts never show together; while the panel travels, its moving edges can still crop either page. In Split and Full Camera chat sits on a card with the Split widescreen webcam card's 25 px corner radius; in the Desktop column a 1 px divider marks the desktop-facing edge instead.
- The compositor's base is a flat stage in the panel colour, so a moving layer never uncovers black; at rest, when the desktop (with Split's column) fills the frame, the desktop is drawn without it. It skips the desktop branch—capture upload, privacy redaction and background/blur—whenever the desktop is fully hidden: a fully covering Away card, a full-frame camera in Full Camera, or any moment the Away card is up over a full-frame desktop-less scene (so as the card lifts off toward Full Camera only the webcam and stage are beneath it, never a retained desktop frame). Full Camera chosen while the card is still lifting off the Desktop instead morphs on from the desktop already uncovered, so that desktop never gives way to the stage and comes back. Screen and camera frames bump a separate `sourceGeneration`, so behind a settled Away card the renderer re-encodes the previous composite instead of recomposing at 30 fps; chat and configuration changes still recompose. The Away card (`AwayCard.swift`) is type only: a Semibold 72 px message (stepping down 4 px to 44 px, then truncating) and an optional Regular 30 px subtitle, centred at 48% height in the area chat leaves free, on flat #16181C (Dark), a flat colour (dark type where WCAG contrast favours it), or the chosen image aspect-filled, blurred (σ 24, clamped edges) under a 55% scrim. Its background (`awayBackground`, `awayRed/Green/Blue`, `awayImagePath`) is separate from the scene background; settings saved before it existed decode to the scene's image or colour. `RenderInputs` draws the card on its image queue whenever its `AwayCardSpec` changes (generation-checked), and the compositor only uploads it to a resident IOSurface. The blurred image is kept in one process-wide cache (`AwayCard.preparedBackdrop`), so each image is decoded and blurred once per path across preview and session renderers. Until a changed card lands the previous one stays up; only a first card needed before any drawing lands is drawn in place, using the cached image if there is one (`AwayCard.cachedBackdrop` never decodes).
- The optional webcam border is a cached rounded-rectangle generator under the camera mask, sized by frame radius plus border width, faded with the same strength as the corner radius during scene changes. Slates use the system font.
- `StudioConfiguration.microphoneSilenced` (explicit mute, or a chosen Away scene with **Mute microphone while away**) is what the mixer applies; it is evaluated once per pull, not per sample, and leaves the saved mute untouched. A silenced microphone also stops driving ducking.
- Desktop webcam sizing uses each frame’s natural axis. Wide interprets both `cameraSize` and `cameraPunchInSize` against the desktop region’s width. Square and Circle interpret both against the fixed 1080 px canvas height, giving 270 px normal and 540 px punched-in sides/diameters at the 25% / 50% defaults regardless of chat width. Normal size is bounded to 12–40%; punch-in is bounded to 40–90%. Missing saved values retain the defaults and Wide frame. Layout settings label the sliders as width or height for the selected frame; the menu keeps only webcam enable and punch-in. Geometry preserves its 24 px corner margins and leaves desktop/chat unchanged; disabling the camera or leaving Desktop clears emphasis without discarding saved choices. `StudioShortcuts` centrally routes Carbon hot-key IDs for annotation (⌃⌥⌘D), punch-in (⌃⌥⌘V), webcam arrangement (⌃⌥⌘M), session start/stop (⌃⌥⌘R) and scenes (⌃⌥⌘1–4, in menu order), with held-key deduplication and separate registration-failure messages. The session shortcut runs `StudioModel.toggleSession` after the Carbon handler returns and activates StreamApp before the app-modal broadcast confirmation.
- Design research distinguished [OBS source scaling from cropping](https://obsproject.com/kb/sources-guide), [Ecamm camera overlays](https://support.ecamm.com/en/articles/3323618-using-overlays), and [Apple's Small/Large Presenter Overlay emphasis states](https://support.apple.com/guide/mac-help/use-video-conferencing-features-on-your-mac-mchlff01c919/mac). None specifies a universal ideal size. Both axes use the same 25% / 50% progression while avoiding chat-dependent Square/Circle dimensions.
- `CameraAnchor` replaces corner state with clamped fractions of the camera's free travel inside the desktop slot, inset 24 canvas pixels. X runs left→right; Y runs top→bottom despite the compositor's bottom-left origin. `cameraAnchor` wins when present (malformed values fall back); only an absent key migrates the legacy `cameraCorner` string. Encoding writes no legacy key. `CameraPlacement` is shared by compositor, schematic and manipulation surfaces, including independent 24 px axis snapping to the nine presets and inverse drag mapping. Corner endpoints preserve the old arithmetic exactly across all shapes and emphasis sizes.
- Direct dragging writes a lock-protected session-only `RenderInputs.cameraDrag`, incrementing generation, without saving or reconfiguring capture on mouse movement. The transition cuts while the override exists. Mouse-up marks the committed anchor, then updates configuration; only `configure` carrying that anchor acknowledges and clears the override, so queued old updates cannot jump home. Preset/explicit configuration changes and cursor dodges retain normal easing.
- `CameraArrangeOverlay` retains one borderless nonactivating panel from launch. Its stable window ID is unconditionally private in `CaptureWindowPolicy`, ahead of annotation/teleprompter visibility, and rejected as a direct window source. Screen changes hide it; invalid layout/camera/window-capture changes dismiss it. It draws only a translucent shaped guide, never camera pixels. `captureRegion` centralizes AppKit metric collection for the pure `DisplayCaptureGeometry.crop`; capture and desktop arrangement use the same menu-bar/Dock boundaries. `CameraDisplayMapping` maps through the sharp aspect-fitted desktop foreground (not the whole desktop slot), then the captured display-local top-left region, then global bottom-left AppKit coordinates. Letterbox coordinates extrapolate instead of silently changing the saved anchor.
- Optional cursor avoidance installs global/local mouse movement/drag monitors only during a session or Live preview with an enabled Desktop webcam and display source; teardown removes them. There is no new timer or polling. A pure hysteresis decision enters at home rect +24 px and returns only outside home rect +48 px. The dodge mirrors X (or Y near horizontal center); overlapping targets, emphasis and manual arrangement/drag bypass it (so the desktop handle cannot flee the pointer). It uses a separate session-only eased renderer override and never persists a temporary position.
- `VideoEncoder.swift` requires hardware VideoToolbox H.264, three in-flight submissions and a six-buffer allocation threshold. `EncodedMuxer` is a ~180-line C FLV writer (no FFmpeg library in the app process): it preserves PTS/DTS as millisecond FLV timestamps, writes each compressed packet with one zero-copy `writev`, and fails after two seconds without transport progress. Its bytes match libavformat's `flv` muxer for this stream except the omitted `encoder` metadata string, which the FFmpeg child replaces on output anyway.
- Encoder input is native 4:2:0: the compositor's final Core Image pass renders straight into VideoToolbox's 420v pool buffers, tagged only with the BT.709 YCbCr matrix, so the hardware encoder does no BGRA→YUV pass and each pooled frame is 3.1 MB instead of 8.3 MB. Decoded output matched the previous BGRA path (same BT.709 video-range values; `EncoderColorTests`). VideoToolbox then tags submitted buffers with the session's BT.709 transfer function, so the program preview reads them explicitly as sRGB (`PreviewFrames.image(_:program:)`); without that the preview is brighter than the output.
- The bundled `ffmpeg` is built by `scripts/build-ffmpeg.py` from the checksum-pinned 9.0.2 source as one static arm64 executable (LGPLv3, OpenSSL statically linked, only `libSystem` dynamically). `--disable-everything` plus explicit components: FLV/`pcm_f32le` demuxers, `h264` (stream-copy probing reads dimensions from AVC extradata) and `pcm_f32le` decoders, `h264` parser, `aac` encoder, MP4/Matroska/tee/FIFO/FLV muxers, file/pipe/TCP/TLS/RTMP/RTMPS protocols and the CLI's audio conversion filters. Adding a feature that needs another codec, format or protocol requires adding it there.
- `AudioMixer.swift` uses fixed-capacity stereo rings aligned to the host clock. AVAudioConverter handles interleaved/noninterleaved input and sample-rate conversion. `microphoneChannels` selects native channels through `channelMap` before conversion: mono N maps to [N−1,N−1] at unity, stereo N/N+1 preserves L/R. Capture explicitly requests native format (`audioSettings = nil`). Core Audio enumerates input counts; both metadata changes and delivered ASBD validate unavailable selections back to device default. Gains/mutes are applied before mixing, absent/disabled sources are silent, late audio is discarded rather than replayed, and mixed peaks are bounded. There is no speaker-monitoring path.
- macOS's direct channel-map path mis-strided interleaved four-channel PCM in 44.1/48/96 kHz fixtures. Explicitly mapped interleaved multichannel input therefore first uses a reusable, same-rate AVAudioConverter layout stage to planar Float32; channel selection and SRC remain in the mapping converter. Unmapped input, mono/stereo devices and already-planar interfaces do not pay for that stage. No per-sample allocation or channel matrix is introduced.
- Microphone compression uses stereo-linked detection, a −18 dBFS threshold, 3:1 ratio, 6 dB soft knee, 10 ms attack and 150 ms release; no makeup gain or AGC. Nonlinear gain calculations run at 1 kHz, with sample-smoothed gain. A linked instant-attack/releasing final limiter caps PCM sample peaks near −1 dBFS without extra latency. This is not an oversampled true-peak limiter; AAC reconstruction may exceed the PCM ceiling.
- Optional AEC uses pinned WebRTC AEC3 through a small static C ABI bridge, before microphone gain/compression. The bridge drives AEC3, WebRTC's 100 Hz high-pass filter and noise suppression directly in upstream AudioProcessing capture order, without an AudioProcessing instance, so there are no per-call format checks, level analysis, statistics, locks or render-output copies. It processes 480-frame blocks at 48 kHz with stereo render and mono capture; AGC and pre-amplification are disabled. The high-pass filter runs ahead of AEC whenever AEC or NS is on, as upstream enforces, and it improves echo removal above 150 Hz. The adaptive subtractor and speech-preserving residual-echo suppression remain active. The delay estimator decimates to 2 kHz, which covers the same ~500 ms search window at half the matched-filter cost; the search starts at zero residual delay, and residual delays under 2 ms do not converge. Samples beyond ±1 are clamped rather than bypassing the block, and NaN is treated as silence. Independent default-off noise reduction runs at its lowest setting on the AEC output, so enabling or disabling it never alters the learned echo path. No creation/reset happens per output block. Measured signal shifts are approximately 9 ms for AEC, 7 ms for NS alone, and 16 ms for both. The 100 ms capture allowance is separate: a physical arrival trace required up to 92 ms for complete reference blocks, so reducing it was rejected.
- An independent timestamp-valid reference ring never enters the broadcast sum. All-other-apps capture is shared when broadcast scope matches; otherwise mic+AEC creates a private all-other-apps reference stream, irrespective of broadcast mute/gain/scope. AEC-only live toggles leave the existing broadcast audio stream running. Missing reference/mic samples advance DSP with zeros but publish raw mic for that block; unavailable reference capture surfaces a bypass reason rather than muting the mic. AEC off releases reference buffers and stops additional reference capture; independent NS may remain active without reference. Both off restores raw stereo upstream of gains/compression.
- Microphone PTS is converted through AVCaptureSession's synchronization clock into host time. Adjacent AEC buffers reconcile up to two samples of timestamp rounding; larger gaps remain invalid. This is not an adaptive sample-clock drift corrector or a qualification of multi-hour/aggregate-device operation. AEC state is recreated on enable/device/session changes, never per output block.
- `scripts/build-aec.py` pins freedesktop webrtc-audio-processing v2.1 commit `846fe90a289f58b7c9303a635142aa2c7caa93e5` and its checksummed Abseil wrap, builds native-architecture release static libraries with `NDEBUG` under ignored `.build/aec`, and caches by compiler/architecture/bootstrap source. On arm64 it forces `-Dneon=enabled`, because upstream's `auto` never defines `WEBRTC_HAS_NEON` and leaves AEC3 on scalar code; the bridge defines the matching arm64/NEON macros for header inline code. The Swift target compiles the bridge; packaging includes WebRTC/Abseil/embedded third-party licenses, patent grant and provenance. Source-release materials must include these exact dependency sources/build inputs too.
- Channel meters observe post-gain/mute/processing signal; the output meter observes the final protected mix. Each reports sample peak (accumulated until one atomic UI read, so transients survive 5 Hz polling) and ITU-R BS.1770 loudness metered per EBU Tech 3341: `LoudnessMeter` K-weights each channel (two biquads, published 48 kHz coefficients), stores 100 ms mean-square blocks, and averages the last 4 (momentary, 400 ms) or 30 (short-term, 3 s), ungated. Bars show momentary LUFS on a −60…0 scale with a −19…−13 LUFS band around −16 LUFS (AES TD1008 streaming and Apple Podcasts target; speech −18) and a 1.5 s hold tick. `AudioLevelTracker` judges the loudest short-term reading (≥ −45 LUFS) over a 2–4 s two-bucket window, so the dip a pause causes in the 3 s average doesn't flip it; clipping latches 2 s on sample peaks ≥ −1 dBFS, and silence needs 6 s without activity. It updates only when a level arrives: no timers. Integrated (gated) loudness and true peak are not measured. Compression configuration lives in Audio settings; the menu omits the gain-reduction readout. Speaker playback volume, integrated LUFS and dBFS are different quantities.
- The compact mixer draws each source's gain fader (`AudioLevelFader`) over its post-processing loudness meter, with a single final Mix meter and short-term LUFS readout on the same geometry so target bands align. The fader is custom rather than `Slider` because NSSlider consumes the mouse-down, making a SwiftUI double-click unreliable: one press gesture handles relative drag (Shift for fine), Option-click, and double-click (a stationary click then a second press at the same spot within the system interval, so rapid nudges never reset). Dragging within ±0.6 dB snaps to unity with an alignment haptic. Accessibility uses a native slider representation with 1 dB steps and a Reset action. Gain and loudness use distinct scales: `AudioFaderScale` maps normalized fader travel to linear amplitude with a cubic taper (unity near 79%, original 2× maximum), while meters remain logarithmic LUFS. Saved gains remain linear; moving a fader does not change mute/enable. Accessibility steps adjust by 1 dB, with silence below −60 dB for downward fine steps and an upward step from silence to −60 dB. Double-click/reset restores unity. Microphone gain remains before compression, so raising it also drives compression harder.
- Visible-menu audio checks reuse the mixer with a bounded 20 ms pull clock. Video defaults Off. Live runs the existing compositor without an encoder at 30 Hz with a four-buffer allocation ceiling; Webcam uses the latest camera frame directly. A generation-guarded serialized transition releases preview resources before recording and on menu close. No recording or broadcast starts; configured chat may connect when Live is on. Gain/mute changes reconfigure the mixer without restarting devices. Off cancels queued camera startup before teardown.
- `MediaOutput.swift` uses private 0700 temporary directories and 0600 named FIFOs, avoiding fragile inherited-FD assumptions or global `dup2` changes in the GUI process. PCM writes preserve partial-write boundaries and fail on a stalled consumer rather than silently dropping bytes. FFmpeg stream-copies H.264 and encodes only AAC. RTMP can reconnect independently of the local recording.
- Source sync offsets are presentation-only, bounded to −500…+1000 ms (positive = later). Each ring's read/late-discard boundary is `programCursor − offsetFrames`, clamped at raw zero; consumed samples clear independently, and negative positions produce startup silence. AEC reads mic and private reference at the same **unshifted raw mic time**; the cleaned block is then read with the mic's presentation offset. Raw capture timestamps are never changed. Negative offsets use real lookahead: both preview and output pull clocks wait `100 ms + greatest configured source advance` (maximum 600 ms), irrespective of initial enable/mute state, while FFmpeg's video-input packet queue uses the same allowance plus headroom. Reserving disabled-source offsets allows live enable without changing the transport clock or rejecting future source samples as late. The maximum source-time span is 1.5 s (plus 100 ms capture allowance and 10 ms DSP block), within the existing two-second rings; there is no extra pixel-frame history or audio-delay allocation. Offset changes restart idle preview; settings lock them during sessions. Stop freezes video and the audio target first, but keeps mic, SCK audio and the AEC reference open until the existing bounded audio/Privacy shield drain completes, so the final advanced interval contains captured samples rather than an artificial silent tail. No new polling is added. This is fixed-error adjustment, not drift correction or a camera capture-time guarantee.
- Recording AAC bitrate is independently saved at 160/256/320 kb/s, default 160; streaming remains 160. `ffmpegArguments` maps PCM once for recording/stream-only or equal rates; unequal Both mode maps PCM twice, with `-b:a:0 160k -b:a:1 <recording>k`, and tee's doubly escaped `select` sends video + audio 0 to FIFO/FLV and video + audio 1 to MP4/Matroska. H.264 is copied once. The existing minimal FFmpeg components suffice (no lavfi or new filters). Filename escaping is separate from nested tee-option escaping.
- Final sample-peak limiter reduction is accumulated independently from mic-compressor reduction and returned under the same atomic mixer lock as levels. `AudioMeters` publishes it on the existing meter cadence, with a separate Limit readout; no additional timer, per-sample allocation or true-peak claim.
- `AudioInputRouteObserver` listens for Core Audio device-list/default-input, input-stream-configuration and transport changes. The model's existing generation-guarded device refresh rebuilds metadata/listeners without capture or polling. Bluetooth/Bluetooth LE input transport warns of possible playback degradation, not a claimed HFP profile; mute never means the hardware was released. This does not detect another application's microphone ownership or infer duplicate signals.
- Microphone disconnect and runtime recovery are serialized on the existing capture queue. Loss stops only that capture, clears queued mic/DSP/converter history, and publishes a non-fatal warning through the existing meter updates; the mixer/output cursor continues timed silence. Reconnect opens only the originally resolved uniqueID (including when System default was chosen), never resets the program epoch, and ignores old session callbacks. Runtime errors receive one immediate restart per connection; another failure waits for reconnect. Notification observers are removed on stop. Initial permission/device-open failures still prevent startup rather than silently starting without a requested mic.
- FFmpeg emits machine-readable progress once per second through a private pipe. Recording confidence uses advancing output timestamps/frame counts and actual file size, not process launch or preview activity. No progress for three seconds after output begins is reported as stalled; startup gets ten seconds. Progress never claims remote delivery: the RTMP slave runs in a fifo with `onfail=ignore`, so the main mux keeps advancing while the stream is down. `MediaOutput.streamEvent` reads the fifo's lines at `-loglevel info`: `Recovery failed: <reason>` (once per retry), `Recovery successful`, `FIFO queue full` (warning; the consumer is blocked on a write or the first connect and packets are being dropped) and `FIFO queue flushed` (the blocked write returned and the queue was discarded). A successful first connect logs nothing, but the queue holds 120 packets and audio alone is about 47 packets/s, so once FFmpeg has muxed three seconds of media the fifo has either sent packets or reported a full queue. Until then the stream reads "connecting"; afterwards a full queue with no flush is "stalled", a full queue within the last 10 s (evaluated on the existing 1 Hz health sample) is "dropping data", and "Streaming" means neither nor a retry is outstanding. Only the reason text is kept, because `Error opening` lines carry the stream key. The 1 Hz health sample also checks free recording space every 10 s. Readers remain open through output finalization.
- Stop releases capture, drains VideoToolbox, closes media transport, and waits for FFmpeg to finalize. The PCM drain awaits the writer task (bounded by the same deadline as before, which cancels it) and FFmpeg exit is signalled by its termination handler (`OutputState.waitForExit`) through the 5 s → SIGINT 2 s → SIGTERM 200 ms → SIGKILL ladder; neither polls. Failure states are surfaced, not silently downgraded to a fake or software path. After session or preview teardown the allocator's freed pages are returned (`malloc_zone_pressure_relief`) so the idle app does not keep reporting the session peak as footprint.

### Optional privacy shield

`PrivacyScanner` exists only when enabled (default off). Changed ScreenCaptureKit frames replace one latest scan slot. Submission, completion and the existing compositor cadence drive a minimum 250 ms scan-start interval (`PrivacyScanner.interval`), without another timer or polling loop; whole-image reads take ~70–100 ms on the test desktop, so a scan normally completes well inside the 0.5 s render delay (not a timing guarantee). Vision fast OCR runs without language correction on the exact copied pixels later composed. Recognition is incremental: the scanner keeps the last recognized input (buffer, options) and its per-observation `OCRRecord`s (line, label, direct matches and continuation boxes, before context). The next scan compares exact luma+chroma 16×16 tiles against it (row-first, so an identical 1662×1080 frame costs ~0.1 ms); identical input reuses the result. Otherwise each changed tile is padded by max(16 px, nearby text height) into a region; overlapping regions merge only when their bounding box is at most 1.25× the area they cover, so a moved window's outline stays a few strips instead of its whole box, and regions grow (strictly outward, at most 32 passes) until each edge is ≥ 8 px from any cached record. All regions are copied into one 420f atlas (shelf-packed, tallest first, 64 px blank gaps wider than Vision joins text across) and read by a single request, because Vision's fixed per-request cost (recognizer creation, detection setup) dwarfs a small region's; `minimumTextHeight` is scaled to keep the whole-image threshold. Atlas boxes map back to whole-image coordinates; an observation spanning two slots throws, and so does a non-420f buffer (history disabled) or an atlas taller than twice the image. Cached records not touching any region (proven unchanged) are kept, and `contextualRedactions` + `mergeRows` run once over the combined whole-image records, so a label and its wrapped value keep their context across a region edge. Initial input, options/revision change, regions over 60% of the image (past that, a whole-image read costs about the same), any atlas error, or a re-read observation reaching a region edge not at the image border takes a whole-image read. Window moves are re-read, not translated: the capture is scaled (1512×982 points to 1662×1080 pixels), so a moved window is resampled at another subpixel phase and never matches its old pixels exactly, and approximate matching could pass changed low-contrast text. A failed read publishes nothing and keeps the reference; the timeline guards the wider bracket it leaves. Geometry/session epochs reject stale completions. Credential patterns match the whole `NAME=value` assignment, and a credential is hidden from its start to the end of its OCR line: fast OCR reads `_` as a space, `=` as `-` or a symbol as `]`, which would otherwise end a match inside the value. Patterns also run on the line with misread symbols read as token characters and, without whitespace, with look-alike digits read as letters (`8pi k&y`); matches map back to the original characters. Entropy tokens need 32+ characters of three classes with at least two digits. A recognized credential label hides its same-row value and the label itself; a line ending in a credential hides the next line to its right within two text heights, and so on along the row. Each line hidden this way is covered from the end of the label or line it continues, because the gap is the same run: a pointer resting on a value splits OCR's read of the row there, and the glyphs beside the pointer would otherwise show. A trailing label, or any line containing a secret, seeds wrap coverage of following lines that start within 1.5 text heights of the row start, or left of the secret's middle (fast OCR interpolates substring boxes across observations joined with another window's text), and look like credential continuations. A detected substring Vision cannot localize covers its whole recognized line. Boxes merge only within a row (vertical overlap ≥ half the smaller height, gap ≤ one height) and are padded by 0.4 × text height horizontally and 0.25 × vertically, never proportionally to width. Rounded covers extend past any source edge they touch, so corner rounding never cuts into text clipped at the capture edge. Camera/chat/audio are outside the OCR surface.

`PrivacyTimeline` owns shield history and completed scans under its own lock. Shielded sessions retain app-owned 420f IOSurface screen copies and timestamped camera copies, with the existing 23-buffer allocation thresholds. Allocation gaps and absence of initial evidence select the neutral waiting scene, never an unplanned raw frame. Screen timestamps are SCK host-clock PTS; camera PTS is converted through the session synchronization clock. Display geometry maps global window bounds to capture pixels. Once per changed shielded display frame, the capture queue snapshots front-to-back visible windows, excluding uncaptured windows/processes. Single-window sources never use desktop window translation.

Detections retain owner-local geometry, the unpadded span/containing OCR row, row pitch, original observation sequence and a small immutable Y-plane patch. Empty scans carry exact or locally confirmed translated positives without turning carry into a new observation or retaining the original full-screen buffer. A placed detection is carried once, as its whole found (unpadded) rectangle with its patch offset unchanged; it is carried unless every piece is already covered by a fresh detection. Because its patch was verified in that frame's pixels, it is covered whole there regardless of listed front windows, so tracking padding never accumulates and a front window listed over it never shrinks the carry to a sliver. Unresolved placement keeps neighboring window-origin candidates as separate rectangles, each clipped against the window listed at that origin. An observed frame also retains its absolute detection. Missing metadata uses known absolute/neighbor candidates rather than full-desktop differences.

Tick `n` runs at host epoch + 0.5 s + `n/30`, selecting screen/camera timestamps no later than epoch + `n/30`. Both completed bracketing scans participate, including the successor of a scanned frame. `PrivacyMotionTracker` runs outside the timeline lock and caches repeated `(epoch, sequence, evidence revision, lane)` plans. Each detection's patch is looked for in its window's current place: first byte-exact at its predicted, previous and unshifted rows; then a sparse signature (both pixels across the strongest horizontal edge of each 16-pixel, quarter-height cell, built once with the patch) ranks vertical shifts within 8 rows of the prediction, then 48, and the whole window for a first placement and every fourth consecutive miss. The nearest four local maxima at correlation ≥ 0.6 get a dense check: whole-patch gain/offset correlation ≥ 0.9 and every 32-column block's residual ≤ 0.35 of the target's contrast, so one differing glyph fails. A row that missed is searched near the shift its window's other rows found, or where the window's recent scroll speed puts it. Listed window bounds lag a dragged window's pixels by up to a frame's step: the first of a moving window's detections searched in a frame probes ±1…±(that step, at most 8) columns and the rest start from the offset it found (or skip the probe when it found none); moving windows search only the nearest 8 rows, since their misses are resampled pixels, never a far scroll. A found detection is covered exactly where it was found, padded by 2 pixels when it moved, clipped only to the capture: the window list can trail or lead the pixels (a window listed a few rows off, a front window listed before it is drawn), and clipping to it would expose text the dense check just saw. The cost is over-cover of at most the secret's own rectangle, e.g. the part of a row scrolled past its window's edge (a match needs only a fifth of its rows inside the window). Unresolved detections produce only secret-width spans at the window's current and neighbouring-frame origins, expanded horizontally by 2 pixels and vertically by one measured row pitch. These `uncertainRows` are solid; positive boxes retain the configured opaque style. Exact rectangle unions have no eight-node bounding-box collapse. Overlapping rectangles are not split into rounded interior seams.

Every tick is encoded and immediately muxed. Idle preview has no lookahead: it uses the newest scan's positive placement, marks unresolved placement degraded, and shows the neutral waiting scene until first evidence arrives. Once the newest scan is older than the 0.5 s delay on the host clock and the shown frame is newer than it, idle preview also gets the changed-tile guard below against that scan (the plan cache keys on this staleness). Monitoring reports “Privacy shield active · 0.5 s delay” or “Privacy shield: unresolved text placement”. Shield-on capture asks ScreenCaptureKit for 420f, the format OCR, tracking and history read, so history copies are exact row copies with no per-frame colour conversion. Shield-off capture remains BGRA/latest-frame, with no window enumeration, history copies or PCM staging. OCR glyph advances and consistent same-pane row geometry may establish a monospace grid; a full sensitive row then predicts at most eight cells on exactly its next row, unless a fresh raw observation classifies that row's start as non-continuation. An absent observation is unknown. Predicted tails track their parent row and do not recursively invent further rows.

The existing 20 ms audio writer stages 48,000 interleaved Float samples in `PCMDelayRing` (0.5 s at 48 kHz stereo), with no per-sample allocation or leading silence. Video PTS and PCM indices still start at zero; FFmpeg retains `-copyts` to preserve that common timeline, not to compensate for dropped initial video. Stop keeps the compositor/capture running through the stop content time (about 0.5 s more), freezes the audio target to `videoFrames × 1600`, completes VideoToolbox immediately and drains PCM including short-session ring tails. The existing audio drain bound is 250 ten-millisecond iterations with the shield, 200 otherwise. No compressed-tail wait remains.

Changed-tile guards (`Plan.guards`) cover pixels no scan read, and only when evidence for the shown frame is missing (`PrivacyTimeline.unreadReference`): no predecessor scan (guard against the successor's frame); no successor by the deadline (against the predecessor's); predecessor and successor more than `maxScanGap` (0.35 s) apart (against the successor's); or a window in which the predecessor found a detection and listed is absent from the shown frame's or the successor's window list (against the predecessor's). A frame that was itself scanned never gets guards. The guard is every 16×16 tile whose luma or chroma differs from the reference inside the capture bounds, merged into vertically stacked runs and rendered as one nearest-sampled tile-resolution mask blended in the censor colour, so cost does not grow with fragmentation. Normal operation (on-time scans, listed windows) produces none; a fully changed screen can be covered only when evidence is missing.

This replacement is a candidate, not an unrestricted no-leak guarantee. A secret absent from all acquired scans cannot be discovered by motion matching; short flashes and wide-interval-only secrets expose that limit. Unknown reflow, clipped/faint patches, lifecycle metadata skew and fractional antialiasing must pass their individual harness gates before release. Beyond the evidence and lifecycle guards above, a failing gate does not authorize broader covers. `PrivacyEvaluation` compares the frozen pre-cutover planner (`current`/`boxesOnly`) and `replacement` using identical scanner publication/carry and deadline-filtered evidence at 0.5 seconds, reporting leak/benign/area metrics (guards count as covers) and per-output tracking CPU/wall cost. End-to-end application CPU and frame cadence are separate measurements; an offline OCR harness does not establish them. Already transmitted content cannot be recalled.

### Compression audit — 2026-09-23

The existing feed-forward stereo-linked compressor uses the quadratic soft-knee curve in [Giannoulis, Massberg & Reiss, JAES 2012, equation 4](https://joshreiss.github.io/documents/2012/GiannoulisMassbergReiss-dynamicrangecompression-JAES2012.pdf), with the smooth branching detector described by equation 16. Attack/release coefficients are computed once; gain computation is decimated to 1 kHz and gain is smoothed per sample. The extra gain smoother is retained rather than changing transient behavior for a speculative optimization. Stereo linking preserves channel balance; only voice is compressed, before the existing post-mix limiter. This is conventional dynamics processing, not loudness normalization or true-peak certification.

A below-knee shortcut avoided `log10` but did not measurably improve optimized runtime. It was rejected: retaining the existing implementation avoids an extra boundary constant and branch without a demonstrated benefit. No dependency, lookahead buffer, background task, automatic makeup gain, or new DSP stage was added.


## Chat, settings and privacy


`TwitchChatFeed` uses per-user [EventSub WebSockets](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/) and the selected broadcaster's channel, independently of output identity. It subscribes to messages, message deletion, user-message clearing and full chat clearing. It deduplicates a bounded 2048 event IDs, enforces keepalive deadlines, drains the old connection during reconnect handoff, retries transport failures with bounded backoff, and clears potentially stale text after gaps. Revocations stop reception. There is no posting API or write scope.

`Chat.swift` loads bundled HTML and serially batches structured events into an owned renderer. It never loads remote HTML. Native pending events are bounded to 256 and the DOM/data model to 100 messages; the color cache is capped at 256. Text uses DOM text nodes, with usernames restricted to hex RGB colors. Official EventSub emote fragments take precedence over case-sensitive, whitespace-delimited catalog codes; channel entries precede globals, with Twitch → 7TV → FFZ → BTTV precedence within each scope. Shared-chat messages from another channel use globals rather than the selected channel's catalog. Missing images and malformed fragments retain plain text. Shared-chat source labels and moderation events are preserved.

`ChatEmoteCatalog` loads public global and channel catalogs from Twitch Helix, 7TV v3, BTTV v3 and FFZ v1. Provider requests run concurrently and identical in-flight requests coalesce. The actor retains at most 36 provider/scope entries with a 30-minute TTL; failures retain stale data for five minutes. Active emote-enabled chat refreshes every 30 minutes, not per message. Third-party responses are capped at 8 MiB during transfer, with no redirects, bounded timeouts and at most 8192 codes per provider/scope. Twitch uses the existing read-only authenticated session; third-party requests send no Twitch credentials.

Catalog URLs and the image CSP allow only HTTPS Twitch, 7TV, BTTV and FFZ CDNs. Rendering uses Twitch's static format, 7TV's `static_name`, BTTV's `.png` variant (the `.webp` route can animate), and FFZ's static `urls`. Images load lazily with asynchronous decoding, preserve bounded aspect ratios, and may form adjacent zero-width stacks. FFZ static flip/grow/color modifiers are supported; animation flags are ignored. FFZ `public`/`hidden` govern adding emotes and picker visibility, not rendering an active set. Private/personal packs, provider update sockets, remote fonts, bot HTML and animated effects are intentionally excluded.

Snapshotting is invalidation-driven, one request in flight and at most 30 Hz. A coalesced one-shot timer runs only when dirty; clean chat has no polling timer. Identical connection statuses do not mutate the DOM. Retina backing scale is measured so snapshots match the requested slot size in output pixels (`SceneGeometry.chatSize`); a scene change resizes the web view in place (`Chat.resize(to:)`) rather than reconnecting. DOM/font/resize/image-load invalidations cover this text/static-image renderer; this is not a general-purpose browser source.

`ChatAppearance` persists individual options with per-field decoding defaults. Presets (Terminal 24 px, Compact 20 px, Large text 32 px, Monochrome 24 px) are value bundles, not a second persisted source of truth; unmatched options display Custom. All use monospace `<username> message`, 1.5 line height and bottom-aligned newest messages. Only whole messages show: `settle()` in `chat.html` hides older messages that would be cut at the top, and a newest message taller than the panel (a 500-character message in Split's 460 px slot under a Square or Circle webcam, or any long one at large sizes) is clamped to the lines that fit, ending in an ellipsis, rather than hidden. The size control spans 20–48 output pixels. The default background is solid `#10151c`; optional translucency is fixed at 90%. Exact Twitch RGB is retained when it reaches 7:1, otherwise blended toward white: names are thin coloured strokes, and the stream's 4:2:0 video halves colour resolution, so luminance has to carry the letters. Contrast calculations for translucency assume white behind the panel, the worst case. Body, metadata and highlight colors meet 4.5:1. This follows [WCAG contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), not full WCAG compliance for raster video; Twitch's [chat documentation](https://dev.twitch.tv/docs/chat/) prescribes no overlay type size. Downscaled playback reduces effective text size.

Appearance edits update the existing preview/output Chat instance instead of restarting EventSub. **Test…** (Settings → Chat) opens a chat preview that uses the configured panel width and offers a selectable native text transcript with manual scrolling; only that test view requests transcript serialization. Moderation clears both the render data and transcript, including after preset changes. Legacy anglbot commands (`!help`, `!fish`, permissions, cooldowns and custom commands) remain bot-owned; the app exposes no command controls and starts no bot process.

Chat stays alive across layout switches when enabled. Turning off Show chat stops and releases WebKit/EventSub, clears its image and skips panel/blur composition; the desktop expands to full width. The macOS WKWebView backing must have `drawsBackground=false` as well as transparent CSS/under-page color. Camera-off clears the image immediately; leaving Desktop preserves only its last screen frame for the short exit morph, and returning restarts real screen capture.

Launching the app does not capture or enumerate private windows, and does not enumerate cameras or microphones: those lists load off the main thread when Settings or setup first appears (camera and saved-microphone start run their own discovery so Continuity/external devices resolve). Source listing and permission requests are explicit UI actions. Settings contain neither OAuth tokens nor stream keys. OAuth credentials and manually saved custom keys use Keychain; automatically retrieved Twitch keys stay in memory. Raw FFmpeg stderr is never displayed or persisted because it can echo an RTMP key. This is a local non-sandboxed app: privileged local inspection is outside this protection boundary.

The quick palette exposes Stroke, Fill, and Highlighter targets. Freehand input uses real tablet pressure, lightweight streamlining and midpoint quadratic interpolation of position/radius; only the unfinished tail is rebuilt. Highlighter coverage uses a single 30%-opacity fill per stroke, avoiding alpha buildup at segment joins. No OCR, text detection, additional screen capture, or background analysis is involved.

**Eraser** defaults to Object; Partial preserves the clear-blend brush. The mode is persisted and snapshotted at contact. Object erasing intersects a swept tip footprint with candidate filled geometry after a bounding-box rejection, including arrowheads and excluding areas already removed by later partial erasers. Hollow shape interiors are not targets. Affected objects are hidden immediately and retained by one undo record per gesture; empty erasures add no history. Undo restores the original objects in place, preserving paint order and partial masks. Geometry remains under the existing storage caps; at most one additional object-erasure record per retained drawable object is possible. Erasing is allowed at the drawing limit, but Clear is still required to reclaim retained undo geometry.

Arrow defaults to freehand ink with a width/length-capped head following its terminal direction. **Straight** switches Pen/Arrow to drag endpoints; Shift snaps these to 15° angles and constrains ellipse/rectangle to circle/square. Canvas-local mouse button events use persisted action mappings (secondary → tools, middle → Straight by default). Raw tablet masks do not identify physical side buttons reliably after driver mapping and are not used for actions. Down/up tracking deduplicates holds. The eight-sector radial picker, color palette, and width picker sit above the canvas and are excluded from capture with the other application UI. `stopDrawing()` dismisses pickers and clears held input.

Freehand arrow heading uses a single anchor trailing the tip by up to 6 pt. This spatial smoothing prevents tiny release reversals from flipping the head, remains independent of event rate and the ink-smoothing setting, and still follows deliberate turns. The tip stays at the actual endpoint; straight-arrow geometry is unchanged. Cost is constant per event with no history buffer.

The mapped Tools button starts a one-shot 250 ms hold timer. A quick release toggles Pen/Erase (other tools return to Pen). Holding shows eight radial sectors, clockwise from north: Colors, Pen, Arrow, Rectangle, Ellipse, Erase, Undo, Highlight. Movement updates only the highlighted sector; release commits it. The center cancels. Colors opens a separate clickable radial palette with Stroke/Highlighter/Fill targets, No fill, and Back to tools; selecting a color does not switch tools. The held-tool panel ignores mouse input so the canvas retains the button sequence; a temporary local monitor consumes tip clicks and forwards side-button releases. Escape, deactivation, drawing exit, or another picker cancels the gesture and removes its timer/monitor. No idle polling is used.

**Hold to straighten** is a separate persisted drawing preference, on by default. The default width is 6 pt; existing saved values are retained. With hold mode enabled, the mapped Straighten button temporarily enables Straight and can convert the active Pen/Arrow gesture to endpoint geometry. Release clears temporary mode without altering the current stroke; the next stroke uses the independent toolbar mode. Escape/Done clears pending holds. Straight Pen/Arrow and arrowheads use the freehand pressure-to-width mapping, retaining last contact pressure on pen-up. Ellipse/rectangle outlines remain uniform at configured width.

The algorithm draws on the distinction between streamlining and outline smoothing in [perfect-freehand](https://github.com/steveruizok/perfect-freehand) and [tldraw's draw documentation](https://tldraw.dev/sdk-features/draw-shape). The arrowhead design follows the proportional sizing principle in [tldraw's arrowheads](https://github.com/tldraw/tldraw/blob/main/packages/tldraw/src/lib/shapes/arrow/arrowheads.ts). This is an independent native implementation, not a bundled tldraw SDK or a full editable-canvas replacement.

ScreenCaptureKit's [application filter with window exceptions](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingapplications:exceptingwindows:)) excludes StreamApp by default and selected apps, then explicitly includes the canvas. **Settings → Capture → Show StreamApp windows** persists an opt-in to include the app's menu, settings, and drawing toolbar in display capture. Changing it updates the active capture filter for both recording and streaming, or refreshes idle preview. The canvas is only added as an exception when its owning app is excluded, so ink remains included in either mode. Individual windows in otherwise included apps are excluded via the same exception list. Refresh/restart after excluded apps reopen. App bundle rules persist; window IDs do not survive StreamApp relaunch. This is an app capture policy, not protection from other capture software or a system-wide confidentiality boundary.

### Wacom configuration research

The separate `~/src/wacom` Tablet Companion discovers global ExpressKeys and supported pen-button settings from Wacom's typed XML. ### Audio research boundary

[EBU R 128 s2](https://tech.ebu.ch/docs/r/r128s2.pdf) distinguishes playback environments and permits different streaming distribution loudness, including −20…−16 LUFS in its described adaptation case. It does not establish one universally enjoyable compressor preset or equate peak meters with loudness. The shipped preset is a conservative engineering choice, not LUFS normalization; the meters report LUFS so the user sets gain. Aggressive gating, automatic makeup/AGC and denoising are deliberately not added without evidence they improve this microphone/use case. Ducking is opt-in; see below.

### Voice ducking research — 2026-09-24

**Decision:** opt-in, default Off, fixed-depth presets on the broadcast mix only. No new timer, allocation or DSP thread: a per-sample peak/hold/one-pole stage in `AudioMixer.pull`, keyed from the mixed microphone and applied to the app-audio bus before metering.

- **Topology.** Streaming tools duck the game/music bus from the mic in the outgoing mix: [OBS's Compressor sidechain](https://obsproject.com/kb/compressor-filter), [Meld Studio's compressor trigger track](https://meldstudio.co/docs/audio/), Elgato Wave XLR Pro ducking configured per mix so "your stream gets ducked while your headphone mix stays full" ([Elgato](https://www.elgato.com/us/en/explorer/products/wave/wave-xlr-pro-give-your-setup-superpowers/)), and RØDECaster Smart Pad ducking of music beds ([RØDE](https://help.rode.com/hc/en-us/articles/9172972164879)). StreamApp has no monitor path, so broadcast-only ducking matches that convention.
- **Controls.** OBS and Meld expose raw threshold/ratio/attack/release. Wave XLR Pro exposes depth, attack and recovery, each low/medium/high, default medium ([alive-project review](https://alive-project.com/en/streamer-magazine/article/18051/)). Windows communications ducking offers 50% or 80% (default) reduction ([ElevenForum](https://www.elevenforum.com/t/change-adaptive-communication-sound-levels-in-windows-11.47293/)). StreamApp exposes depth presets only; timing is fixed because the published ranges overlap.
- **Depth.** Narration over music about 6 dB, typically 4–9 dB ([Audio Tool Kit](https://audio-tool-kit.com/blog/audio-ducking)); creator starting range 6–12 dB ([CapCut](https://www.capcut.com/create/audio-ducking-for-clear-dialogue-in-video)); VB-Audio's Voicemeeter manual uses −10 dB as its example. OBS's documented start (32:1 above −36 dB) is level-dependent: speech peaking near −18 dBFS gives about 17 dB. Presets: Light 6, Medium 12, Deep 18 dB. DPP and older Netflix guidance recommend speech at least 4 LU above background ([Torcoli et al., AES 156](https://arxiv.org/abs/2405.17364)); every preset adds at least that much separation to an already balanced mix.
- **Timing.** OBS: attack 100 ms, release 600 ms. Audio Tool Kit: attack 20 ms, hold 200 ms, release 400–800 ms. CapCut: attack 30–80 ms, release 250–700 ms. Shipped: −36 dBFS sample-peak key (OBS threshold), 200 ms hold, 50 ms attack and 600 ms release time constants.
- **Genre.** No vendor publishes genre-specific presets; the mapping is an engineering recommendation. Gaming/just-chatting streams duck game audio or background music. Music-production streams usually present the app audio as the content, so ducking audibly alters the track while the host explains it; Off stays the default for the Ableton workflow above.
- **Risks.** Speaker bleed into the mic keys the ducker from the music itself (pumping); headphones or AEC avoid it. A fixed −36 dBFS key assumes the mic is gained toward the −16 LUFS meter target; very quiet speech may not trigger and loud room noise can. Muting or disabling the mic releases ducking because the key is post-mute.

### Ableton / OBS audio qualification

**Decision:** retain native ScreenCaptureKit + AVFoundation + the existing timestamped PCM mixer. No virtual driver is required for ordinary Ableton stereo capture. Keep the performer’s monitoring in Live/the interface, not in StreamApp. Prefer one wired interface/headphones for playing; AirPods are a convenience listening path, not a low-latency reference.

**Observed local configuration:** Ableton Live 12.4.3 and OBS 31.0.1 are installed. Before this change, StreamApp's saved audio enabled both system audio and the default microphone, at unity gain, with mic compression enabled. OBS's saved `Untitled` collection has an `ABLETON_SCENE` using the `ABLETON` ScreenCaptureKit video source targeted at `com.ableton.live`; the saved current `Dev Time` scene uses a different screen source. Explicitly configured OBS profiles inspected use 48 kHz stereo; the testing profile has no explicit Audio section. These are saved-file observations, not proof of current device routing. OBS/Live settings, audio hardware settings, permissions and stream credentials were not changed.

**Capture change:** visual SCStreams have audio disabled. A separate 48 kHz stereo audio stream uses a display-backed application filter independent of visual window/display selection and exclusions. Its 2×2/1 fps screen output is discarded, following OBS's screen-backed audio pattern; no additional compositor/encoder is created. A nonempty bundle ID includes only the current matching applications, while empty explicitly selects all other apps. Missing apps reject startup; termination of a selected process stops/finalizes the session rather than silently falling back or reacquiring another process. Normal scene/video-source changes leave the audio stream running. Preview uses the same policy. Application attribution is macOS's responsibility, not an isolation boundary between arbitrary helper/child processes.

**Migration:** configurations without `systemAudioApplicationID` disable app audio on decode. Keeping the old enable bit would silently broaden window/exclusion-scoped audio to all apps. Other choices are retained. Once a scope is chosen and enabled, it persists normally. The menu labels the audio scope and warns about default-microphone selection.

#### OBS configuration for this machine

OBS 31.0.1 satisfies the documented OBS 30+ native macOS Audio Capture requirement [O1]. The saved Ableton video source is not the same thing as a persistent dedicated music source.

1. Add **macOS Audio Capture → Application → Ableton Live**, with Live running. Use the same existing audio source in each required scene (or a shared audio scene included in each), rather than separately instantiating captures.
2. Disable/mute the audio contribution from Ableton's Screen Capture source and any overlapping desktop/virtual feed. Do not disable the new dedicated source when switching to a camera scene. OBS 28/29's older screen-capture method removes audio when hidden; “hide the screen source” is not a portable audio-only recipe [O1].
3. Keep **Settings → Audio → 48 kHz → Stereo** for this route. Choose a specific working microphone; the saved headphone-input UID needs verification before relying on it. Do not also add that same mic as a duplicate scene source.
4. In **Advanced Audio Properties**, keep music **Monitor Off** when already listening through Live. “Monitor Only (mute output)” does not send that source to the audience; “Monitor and Output” can double it if the monitor device is captured.
5. Assign the complete audience mix to the streaming track; assign optional isolated music/mic tracks to recording. Verify the chosen player/editor exposes multiple tracks. Configure VOD track separately if desired; recording stems alone do not alter the live mix.
6. Measure camera/voice/music sync using the file, not a delayed browser stream. Use per-source sync offsets only after stable routing is established. Record every scene transition, then listen back.
7. Use **one** fallback virtual route only if native capture fails the actual Live bus/channel requirement. BlackHole 2ch + a deliberate Multi-Output device is free; Loopback provides explicit app/channel/monitor routing [O2]. Avoid feeding both native and virtual copies into the mix. Do not alter system default output just to capture audio when native app capture already works.

#### Required hardware qualification before treating a setup as show-ready

- AirPods output with mic disabled; AirPods output with explicit Mac/USB mic; open the actual chat/browser/dictation apps. Check playback quality, recording and perceived playing latency. Repeat reconnect/automatic-switch recovery in a private session.

- Real camera clap/transient at beginning and end of the intended stream duration; sustained CPU load with webcam/chat; test device removal, app quit/relaunch, display removal and sleep only in a private recording.

## Release boundary

Local builds default to ad-hoc signing on fresh checkouts and can be installed without an Apple certificate. The published v1.2.0 ZIP passed signature, ticket, uncached Gatekeeper and pre-distribution checks on the development Mac.
