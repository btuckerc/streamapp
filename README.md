# StreamApp

Record your screen or stream to Twitch from your Mac’s menu bar.

## Install

The supported release install is for Apple silicon (arm64) Macs running macOS 26 or newer. Download the latest **StreamApp** ZIP from the [GitHub Releases](https://github.com/btuckerc/streamapp/releases/latest) page, then in Finder:

1. Open the downloaded ZIP.
2. Move **StreamApp.app** to your **Applications** folder.
3. Open **StreamApp** from Applications.

The release app is Developer ID signed, notarized, and stapled. No Apple developer certificate, `xattr` bypass, or other signing setup is required. The GitHub release also provides bundled FFmpeg in the app and a separate corresponding-source archive asset; keep that asset with the release materials when redistributing.

### Build from source

Source builds require macOS 26 or newer, Xcode, Python 3, and Homebrew. **No Apple signing certificate is required.** With [Homebrew](https://brew.sh) installed, quit any running StreamApp instance and run:

```sh
brew install openssl@3 pkg-config meson ninja
python3 scripts/build-app.py --install
```

Open **StreamApp** in your home folder’s **Applications** folder. To build without installing, omit `--install`; the app is created in the project folder.

To try a change, quit the running StreamApp, then run the install command again and reopen it; `--install` refuses to replace a running app.

The first build downloads and compiles pinned WebRTC/Abseil sources for local echo cancellation and a pinned, checksum-verified FFmpeg 9.0.2 source release; later builds reuse both static dependencies. For direct `swift build` or `swift test`, run `python3 scripts/build-aec.py` first. No WebRTC or FFmpeg runtime installation or network service is needed by the installed app. Homebrew `ffmpeg` is only used by the developer scripts `scripts/rtmp-receiver.py` and `scripts/verify-media.py`.

Fresh checkouts use local ad-hoc signing automatically. You can also request it explicitly with `--identity -`, including with `--install`. These builds are not notarized for distribution, and macOS permissions may need reapproval after rebuilding.

An optional `--identity` or `APPLE_SIGNING_IDENTITY` selects an installed Apple Development or Developer ID Application certificate. Existing local signing pins are preserved, so established developer builds keep their stable identity; an unavailable selected certificate fails rather than silently switching identities. Use `--identity -` to opt out for a local build without changing the pin.

## Developer ID release build

Release mode requires an installed **Developer ID Application** certificate and does not modify the local development signing pin or install the app. It packages the native host architecture only:

```sh
python3 scripts/build-app.py --release \
  --identity "Developer ID Application: Your Name (TEAMID)" \
  --version 1.4.0 --build-number 11 --output /absolute/path/StreamApp.app
```

The output path must not already exist. `scripts/build-ffmpeg.py` builds a minimal, static, LGPLv3 FFmpeg command-line tool containing only what StreamApp uses (FLV/PCM input, H.264 stream copy, AAC encoding, MP4/Matroska/tee/FIFO/FLV output, file/RTMP/RTMPS with statically linked OpenSSL). Its exact configuration, source checksum and licenses are recorded in the app; redistribution requires corresponding source and applicable license notices. A nonfree FFmpeg configuration is refused.

This command signs only; it does not notarize or publish. Use the shared sibling checkout's `python3 ../mac-releases/release.py --help` for the complete `build streamapp` → `notarize` → `verify` → `draft` → `publish` workflow. Stream App requires `--corresponding-source /path/to/archive.tar.gz` when building a release; that archive is distributed alongside the app. This must contain the exact corresponding dependency sources/build materials, not merely a source URL or an arbitrary source snapshot. The pipeline does not certify license compliance.

## Set up

1. Follow the setup window. Allow screen, camera, and microphone access when needed.
2. Choose the screen or window you want to record.
3. Pick a scene. Turn your webcam and audio sources on or off.
4. Choose **Record**, **Stream**, or **Both** in the menu, then click **Start** or press **⌃⌥⌘R** from any app. **Record** stays local even with a saved streaming setup; **Both** streams and saves a local copy. Click **Stop** or press **⌃⌥⌘R** again when finished.

**Scenes.** The menu and **Settings → Scene** show one scene card: the preview (or, with the preview off, an animated diagram of the scene) joined to a picture button for each scene. Click one, or press **⌃⌥⌘1**–**⌃⌥⌘4** from any app, live or idle. Scenes move rather than fade: the screen, webcam and Split column glide to their new places in 500 ms, with chat following a beat behind, and chat turned on or off slides in from, or out past, its edge at full size. Hiding never animates: going Away covers everything on the next frame (the card then settles from 103% to full size), and a webcam turned off disappears at once, even while an earlier switch is still starting its sources. Leaving Away, the next scene is already in place and the card lifts off the top of the frame. Program motion ignores macOS Reduce Motion, which governs this Mac's interface rather than what viewers see; the scene diagram honours it. **Split** and **Full Camera** need the webcam: while it is off their buttons are dimmed with a crossed-out camera, and choosing one (or its shortcut) beeps and says to turn the webcam on; it never turns the webcam on for you. Turning the webcam off in Split moves to **Desktop**; in Full Camera the Away card covers it with the microphone left live (choose Away yourself to get **Mute microphone while away**). Turning the webcam back on never changes the scene. The desktop never appears unasked. A saved camera scene without the webcam opens in the same fallback. Entering a desktop scene keeps the current scene on air until the first new desktop frame is ready (at most 1.5 s), and leaving one changes the scene before screen capture stops, so switches never show a blank or stale desktop. If the webcam has no picture yet (starting, or disconnected), Full Camera shows the Away card (it lifts off once the webcam is ready), Split shows chat alone and Desktop no webcam, rather than a placeholder.

| Scene | What viewers see | Captured |
|---|---|---|
| **Desktop** | Your screen, a floating webcam you can drag and punch in, chat in a side column | Screen, webcam |
| **Split** | Your screen beside a column holding the webcam card with chat below it (column follows the chat side). Without chat the webcam becomes a full-height portrait card; with neither, the screen fills the frame | Screen, webcam |
| **Full Camera** | Edge-to-edge webcam with chat on a glass panel | Webcam only |
| **Away** | Your message (default “Be right back”) and an optional subtitle, set in large type on a dark, colour or blurred-image background; chat stays on screen | Nothing: screen capture stops, the webcam is hidden |

Away also silences the microphone by default (**Muted while away** shows in the menu; your own mute setting is untouched). Change the message, subtitle, background (**Dark**, **Color** or **Image**; light colours get dark type), or keep the microphone live in **Settings → Scene → Away**. Moving between Desktop and Split keeps the running screen capture; only Full Camera and Away stop it.

While a session runs, the menu shows each output on its own line: **Recording · 12:34 · 1.2 GB** and, when streaming, **Streaming** (with the time when there is no recording). FFmpeg reports nothing when a stream connects, so the stream line reads **Stream connecting…** until about three seconds of media have gone out; **Streaming** then means the connection is taking data and FFmpeg has reported no error. A connection that stops taking data shows **Stream stalled**, one too slow for the stream shows **Stream dropping data** for ten seconds after each loss, a dropped or refused connection shows **Stream reconnecting** with the reason (in **Both**, the recording continues), and **reconnected** follows a recovery. The Start button names what it is waiting for (**Getting key…**, **Starting…**, **Saving…**); while it fetches a Twitch stream key it is a **Cancel** button. If a session stops with an error, or a shortcut start cannot begin, the menu opens to say why without taking focus from your app. ⌃⌥⌘R returns focus to your app after the broadcast confirmation.

Recordings go in **Movies → StreamApp**, named by local start time like screenshots (`StreamApp 2026-11-06 at 13.07.05.mp4`; a number is added only if that name exists). Change the folder in **Settings → Output**. Recording needs at least two minutes of free space to start; below about ten minutes the menu warns **Disk almost full** with the time left. After a session, the menu shows what was saved (**Saved · 12:34 · 1.2 GB**, or **May be incomplete** after an error) with **Open** and a Finder button.

**Settings → Output → Recording format** chooses **MP4** (default) or **MKV**; both contain the same H.264 and AAC streams. MP4 uses FFmpeg's hybrid fragmented mode, the same approach as OBS's default [Hybrid MP4](https://obsproject.com/kb/hybrid-mp4): if the app crashes or the Mac loses power, everything written so far can be recovered, and a normal stop produces a regular MP4 that QuickTime, Finder, and editors open directly. MKV also survives crashes, but QuickTime and Finder cannot play it.

**Settings → Output → Privacy shield** is **off by default**. When enabled before starting, it delays screen, camera and audio output by a fixed **0.5 seconds**. Each video tick is composed late using completed scans; detected credentials/passwords receive opaque covers from their first frame and follow their windows during drags. **Censor style** offers a solid bar (default), rounded bar or stripes, and **Censor color** sets its colour (near-black by default). Blur and pixellation are not offered because hidden text can be recovered from them. Optional personal-information detection (on by default) also covers email, phone, card and SSN patterns. Video is never frozen or dropped. Until the first scan completes, the output shows a neutral waiting scene. Program preview shows the delayed redacted output; idle preview and camera-only preview stay live, and idle preview is covered until its first scan completes. Stop renders through the stop instant before draining output. Shielded sessions keep bounded raw-frame history, allocated on demand: up to about 70 MB of screen frames at 1080p plus the same count of camera frames at the camera's size.

OCR runs at most four scan starts per second and, once a screen has been read, rereads only regions around pixels that changed, packed together into one OCR request (a ticking clock or blinking caret costs a small region; a dragged window, its old and new outlines and the window itself). A detection stays covered while its pixels are unchanged, with no time limit, and moves with its window, including while OCR misses it mid-drag; covers are window-local, so moves leave no screen-space trails. Changed pixels are covered with solid 16-pixel blocks only when scan evidence is missing for that frame: no completed scan before it, no scan after it by the time it is shown, scans more than 0.35 s apart around it (a slow or failed scan), or a window holding a detection that closed or disappeared. In normal operation (scans arriving on time, windows listed) no blocks are drawn; in the drag benchmark they appeared only in the frames after the secret window closed. Idle preview has no delayed output to wait for: once its newest scan is more than 0.5 s old, everything changed since that scan is covered until a scan reads it. A credential is covered from its start to the end of its text line, label included, so underscores or OCR misreading `_` as a space or `=` as `-` do not leave the rest of the value visible. When the mouse pointer splits a secret line in two for OCR, the cover also spans the gap under the pointer. Values beside credential labels such as `aws_secret_access_key =` or `DB_PASSWORD:` are hidden even when the value itself looks ordinary; wrapped credential values are covered too. Covers are padded by a fraction of the text height and only merge within a row. **Recall is best-effort, not a privacy guarantee**: text that appears and disappears between two scans (under about 0.35 s), and small, stylized, obscured or unrecognized text can be missed (spell-check underlines can stop recognition; the last few characters of a long wrapped key on their own short row can be missed), and unrelated text can be masked, including text OCR merges from an adjacent window. The shield costs CPU: about 21–27% of one core with the shield on versus about 11–12% off, measured on a text-dense 1662×1080 desktop (about 21–23% with a still window, 26–27% while one is dragged back and forth). The shield scans the screen/window source, not webcam, chat or audio, and cannot protect other recording apps. Avoid displaying real secrets even with the shield enabled. Change shield settings only while stopped.

Choosing Stream or Both with missing or invalid connection details opens **Connect streaming**. Choose Twitch and connect your account, or choose Custom RTMP and save its server/key in Keychain. Setup never starts a broadcast: return to the menu and press Start, then confirm. Stop the current session before changing output modes.

StreamApp asks for camera, microphone, or Screen Recording access when you first turn on a source that needs it, following macOS convention. If access was turned off in System Settings, turning the source on offers **Open System Settings** instead. A one-line notice appears at the top of the menu, and beside the affected setting, only when an enabled source lacks access; unused sources never nag.

In onboarding's **Prepare** step, **Fit Dock to 16:9** sits beside **Show chat** below the preview. Set Fit before starting a local preview; the existing Dock confirmation and restoration behavior apply. New setups enable system audio by default. **Audio from** in Prepare selects all other apps or an isolated app: open Ableton, choose **Refresh List** at the bottom of the menu, and choose it to exclude unrelated alerts. Saved disabled/isolated choices and the older audio-scope privacy migration remain unchanged. Screen Recording authorization is still required; you can turn audio off without granting it.

**Settings → Capture → Include menu bar** controls whether macOS's menu bar appears in display capture. It is on by default, is saved, and does not affect individual window capture or your actual desktop. Disabling it crops the selected display's top reserved strip (including the notch safe area) before fitting the remaining desktop into the output canvas. This intersects with the Dock-fit crop without changing the Dock-fit target or the 1080p output size.


**Settings → Scene → Background** fills unused space around display/window content: Black (default), Color, Image, Blurred desktop, or Mirrored wallpaper. The desktop stays sharp and uncropped. Blur has an amount slider; images are imported into app-owned storage, with a fallback color for transparency or a missing file. Mirrored wallpaper reflects a cached snapshot of the selected display's current rendered wallpaper, not recorded windows; unavailable wallpaper uses the fallback color. It refreshes on desktop/source changes, rather than continuously following wallpaper animation. These controls affect the program preview, recordings and streams, not the physical desktop or the camera's crop.

The menu is one panel with no scrolling: the scene card, a row of Webcam, Punch in, Chat, Annotate, and Clear buttons, one row per audio source, and session start/stop. The chip in the card's corner reads **Preview**, **Webcam**, or **Preview off**: click it to switch the preview on or off, or use its arrow for **Preview**, **Webcam only**, or **Off**. **Webcam only** says **Webcam is off**, or **Starting webcam…** until the first picture, instead of showing a black frame. Video preview starts off and shows the scene diagram. Turning the webcam or chat on or off while previewing changes only that source, so the preview keeps playing. While a session runs, the card shows **REC** (recording or rehearsal), **LIVE**, **LIVE · REC**, or, in orange for a Twitch test stream that viewers cannot see, **TEST** or **TEST · REC**. “Live” always means a public broadcast. Closing the menu stops its idle capture unless Scene settings still needs it. Preview does not start a recording or broadcast. The menu-bar icon, like the app icon, is a screen with a webcam circle breaking its lower-right corner; the circle is hollow when idle and fills during recording or broadcasting.

**Webcam sizing** uses the frame’s natural axis. **Wide** uses the Desktop region’s width: the 25% normal default grows to exactly 50% when punched in. **Square** and **Circle** use the canvas height for both states: 25% normally and 50% when punched in, or 270 px and 540 px on the 1080p canvas. The separately saved **Size when punched in** is bounded to 40–90%; normal size is bounded to 12–40%. Both preserve the selected relative position without moving desktop or chat. Set frame, both sizes and position in **Settings → Scene**. Press **Control–Option–Command–V**, or the menu's **Punch in** button, to toggle emphasis. Camera-only motion uses a gentle 600 ms Bézier transition. Punch-in never enables a disabled webcam or switches to Full Camera, and clears when the webcam is disabled, you leave Desktop, or the app restarts.
The **Webcam** section in **Settings → Scene** offers **Wide**, **Square**, and **Circle** frames, and a **Border** (None, Thin, Bold) in a colour you choose, in Desktop and Split. Rows that don't apply to the selected scene are hidden. The camera uses clean clipping and a quiet separation shadow; Full Camera remains edge-to-edge and unstyled.

**Move the webcam** by dragging it in the scene card (menu or Settings) — live or as the diagram — or in the setup diagram without opening video capture. Edges and centers snap within 24 canvas pixels; hold **Option** for free placement. **Settings → Scene → Webcam → Position** offers nine presets by name; a dragged position shows **Custom**. **Arrange on Desktop**, at the bottom of that menu, in the Webcam tile’s context menu, or **Control–Option–Command–M**, shows a private dashed handle over the webcam’s mapped desktop position—no second video preview. Drag, then press **Escape**, **Return**, **Done**, or the shortcut again to finish. This handle never appears in capture, even with Show StreamApp windows enabled. Desktop arrangement requires display capture; for single-window capture, drag in the scene card instead.

**Move aside when the pointer is near**, in the same Webcam settings section, is off by default. During a session or live preview with display capture it moves the webcam to the opposite side when the pointer approaches, returning home after the pointer leaves a larger safe area. It pauses during punch-in, desktop arrangement and direct dragging, and does nothing when the two positions overlap. Temporary dodges never change your saved position.

Settings is a standard macOS preferences window: a toolbar of pane icons (Capture, Audio, Scene, Chat, Prompter, Drawing, Output) with the selected pane's name as the window title. Rows that don't apply are hidden rather than greyed out — for example microphone options while the microphone is off, chat styling while chat is hidden, Privacy shield options while it is off, and Streaming or Recording options when **When you press Start** doesn't use them. Once a setting differs from its default, a reset arrow appears beside its name; click it to restore that preference. **Restore Defaults…** at the bottom requires confirmation, restores any active Dock fit first, and resets configuration plus drawing preferences. It preserves recordings, saved credentials, onboarding completion, and macOS permissions.

Each audio row has a mute button, a level verdict (**No sound**, **Too quiet**, **Good**, **Too loud**, **Clipping**), a gain readout, an enable switch, and a fader drawn over that source's live loudness meter, so dragging shows its effect immediately. Meters show perceived loudness (ITU-R BS.1770 LUFS), not peaks. Aim for the green band, −19 to −13 LUFS around the −16 LUFS streaming target (AES TD1008, [Apple](https://podcasters.apple.com/support/893-audio-requirements)); a tick holds the recent loudest moment. **Clipping** means sample peaks reached −1 dBFS. The dB readout is the gain adjustment, not the measured signal level. Double-click or Option-click the fader to restore 0 dB without changing mute/enable; Shift-drag adjusts finely, and dragging snaps to 0 dB. The **Mix** meter shows what viewers hear, with its 3-second loudness in LUFS. Enable switches remain separate because disabling releases capture while mute only silences the mix. Microphone gain is before compression: increasing it also drives compression harder. Compression lives in **Settings → Audio → Voice processing** (shown while the microphone is on), not the quick menu.

**Settings → Audio → Voice processing → Echo cancellation** optionally reduces speaker playback entering your microphone, before microphone gain/compression. It is saved independently of compression and defaults off. It uses other apps' playback privately as a reference even when broadcast app audio is disabled, muted, or limited to one app; the reference itself is never added to your recording/stream. Your selected system-audio feed stays stereo and unchanged. Enabled AEC makes the microphone mono, removes rumble below about 100 Hz, and can soften quiet speech or musical input; use bypass/headphones for critical music. The status shows when cancellation is active or bypassed because its reference is unavailable. This is in-app WebRTC processing, not macOS Voice Isolation.

**Noise reduction** is a separate, saved, default-off switch in the same section. It reduces microphone hiss/fan noise with or without AEC, without capturing playback when AEC and app audio are off. It processes the mic as mono and can soften very quiet speech or music. Leave it off for voice fidelity; enabling it adds approximately 7 ms of signal delay. Toggling it does not reset AEC's learned echo filter.

**Settings → Audio → While you talk → Lower app audio** (shown while both the microphone and app audio are on) lowers app audio in the stream and recording while you talk: **Off** (default), **Light** (−6 dB), **Medium** (−12 dB) or **Deep** (−18 dB). What you hear locally is unchanged. Speech is detected on the microphone as mixed (after gain, mute and processing) above −36 dBFS; ducking holds 200 ms through pauses, reaches depth with a 50 ms time constant and recovers with 600 ms. Light suits talking over music, Medium gameplay commentary, Deep background music. Leave it off when the app audio is the performance, such as an Ableton session. With speakers, playback reaching the mic can trigger ducking; use headphones or Echo cancellation.

**Settings → Audio → Microphone → Channels** selects the device default, one centered mono input, or a stereo pair. Mono duplicates the selected channel equally into left and right at unity gain; it does not sum all interface inputs. A device with fewer channels resets an unavailable selection to Device default. For musical inputs, deliberately turn off compression, echo cancellation and noise reduction. A Bluetooth-input warning follows device/default-route changes; disabling or reselecting the microphone, not muting it, releases the input.

**Settings → Output → Recording → Audio bitrate** offers AAC **160** (default), **256**, or **320 kb/s**. Streaming stays at 160 kb/s; Both mode uses two AAC encodes only when the recording rate differs. These are lossy stereo recordings, not isolated tracks or lossless masters. The mix row's **Limit** readout shows final sample-peak limiter gain reduction separately from microphone compression. If it rides continuously, reduce source gains or leave more headroom upstream; it is not true-peak certification.

Each source has a saved **Sync** offset (**Settings → Audio → Sync → Delay app audio / Delay microphone**, shown for enabled sources), **−500…+1000 ms** in 10 ms steps. Positive plays that source later; negative advances it by buffering output (up to 500 ms extra transport latency, on top of the existing 100 ms delivery allowance). Lookahead is reserved even for an initially disabled source, so enabling it during a session retains sync. Set offsets before starting and measure with a recorded clap/transient. Startup may be silent for delayed sources; advancing trims their early audio. Stop freezes the last video timestamp but keeps audio capture open through the final advanced interval and any Privacy shield tail. A fixed offset does not correct clock drift or variable Bluetooth latency.

If an active microphone disconnects, recording/streaming continues with that source silent and a warning. Reconnecting the same device resumes capture on the existing program clock; another input is never substituted. A microphone runtime error gets one restart attempt, then waits for reconnect. Other audio and video keep running.

**Settings → Capture → Show StreamApp windows** controls whether the menu and app windows appear in display recordings and streams. It is off by default, saves your choice, and can be changed during a session. Annotation ink stays visible either way.

**Fit Dock to 16:9**, in **Settings → Capture** and onboarding's **Prepare** step, temporarily shows and resizes a bottom Dock to fit the desktop into the scene. It remembers both the previous size and auto-hide setting, including across app restarts, and restores them when turned off. Chat and its width change the target. Applying or restoring settings briefly restarts Dock; System Events permission is no longer required. Capture follows the measured area above the Dock, including the menu bar, as items appear or disappear. If macOS cannot reach the ideal height, the whole usable desktop fits with padding rather than losing content. Restoration waits for the hidden Dock’s pre-fit desktop boundary before clearing its recovery journal. Newer manual size or visibility choices are kept. Handoff and Dock items are never changed. StreamApp does not reposition other apps’ windows.

## Notch teleprompter

Set **Mode** to **Off**, **Transcript**, or **Twitch chat** in **Settings → Prompter**. Teleprompter controls live only in Settings, not the quick menu. The pure-black panel extends down from the physical display camera—not the webcam image in your video—with three transcript lines or the latest six chat messages. It prefers the built-in notched display.

In Prompter settings, **Save Template…** creates an editable Markdown script; **Open…** loads an existing Markdown script and **Reload** reads saved edits. Put `---` on its own line between cues. Longer cues wrap into three-line pages. **Left / Right** move backward / forward globally while the transcript is expanded. The arrows pause when collapsed, while editing StreamApp settings, or while choosing files.

Click anywhere on the panel to retract it; the fixed chevron immediately left of the notch expands it again without losing your place. Twitch mode uses the channel in **Settings → Chat** (blank follows your connected account) independently of **Show chat**.

The entire teleprompter, including its chevron, is **private in StreamApp by default**, even with **Show StreamApp windows** enabled. **Visible in stream and recording** explicitly includes it in display capture on that screen. It is not added to Full Camera or other single-window sources. This privacy rule does not hide it from other recording apps.

## Producing music in Ableton

1. Open Ableton. In **Settings → Audio**, choose **Refresh List** in the **Capture audio from** menu, select **Ableton Live**, and turn on **App audio**. Video selection and scene changes do not change this audio selection.
2. With AirPods, use them for playback only. Choose the Mac or a USB/interface microphone explicitly, or disable the microphone. **Mute does not release a microphone**; even the visible menu's level check opens an enabled mic. Other apps can also open the AirPods mic and affect playback.
3. With speakers, disable the microphone for clean music-only capture. For voice plus music, headphones avoid speaker bleed and delayed doubling. Monitor directly through Ableton/interface, not the stream.
4. Use wired headphones for latency-sensitive playing. Start with a stable Ableton buffer (128–256 samples is a starting point, not a guarantee), choose the intended stereo main output, and use **Standard** macOS Mic Mode for musical inputs.
5. Record a short check: play music, open another audio app, change scenes, speak, stop, and replay the file. Check left/right, unwanted cue/metronome/alerts, doubling, clipping, and camera sync.

**Upgrade note:** older saved configurations captured audio according to video filters. App audio is disabled once when loading those settings so the upgrade cannot silently expose previously excluded apps. Choose an audio source and re-enable it. **All apps** includes alerts and is independent of visual exclusions.

OBS 30+ has a native **macOS Audio Capture** source: target Ableton, keep it in every required scene, disable duplicate desktop/screen-capture audio, and leave monitoring **Off**. BlackHole/Loopback are optional routing fallbacks, not prerequisites.

See the [audio risk matrix, OBS checklist, and qualification limits](docs/architecture.md#ableton--obs-audio-qualification).

## Twitch

In **Settings → Output**, select **Twitch** and click **Connect…** beside **Twitch account**. Approve **StreamApp by btuckerc** in your browser. StreamApp requests only chat-read and stream-key-read permissions, stores OAuth credentials in macOS Keychain, and retrieves your key automatically when starting a confirmed Twitch stream. No manual key or separate chat server is needed. Twitch is the default when no service choice is saved; an explicitly saved **Custom RTMP** choice is retained. **Record** stays local.

In **Settings → Chat**, or onboarding's optional Twitch section, enter a username, `@name`, or Twitch channel link. **Apply** appears only after editing; connected accounts check that the channel exists before saving. Blank uses your connected account's channel. **Test…** shows messages without recording or broadcasting. Turn on **Show chat** to include them in the program.

Under **Chat → Appearance → Preset**, choose **Standard** (24 px), **Compact** (20 px), **Large text** (32 px), or **Monochrome** (24 px, no name colors, emote images or highlights). Individual tweaks show as **Custom**. All use restrained monospace `<username> message` formatting; sizes refer to the 1080p output, not the scaled preview. Chat keeps that size in every scene: it is laid out for the space it gets (the Desktop column, the 560 px space under the webcam in Split, the Full Camera panel) instead of being shrunk to fit, and in Split and Full Camera it sits on a rounded card matching the webcam's. Only whole messages show; a newest message too long for the space shows as many lines as fit, ending in "…". Appearance changes apply without reconnecting. The chat preview's **Text** view is selectable.

Appearance also controls Twitch colors, emotes, command/mention highlighting, timestamps, the channel heading, connection status and background. Dark name colors are brightened to reach 7:1 contrast, which keeps them legible after the stream's colour subsampling.

**Emotes** is on by default: Twitch plus public global/channel catalogs from **7TV, BetterTTV and FrankerFaceZ**, with no extension or separate provider login. Codes are case-sensitive (`SAJ`, not `saj`). Images are static to avoid continuous animation work; adjacent zero-width modifiers can layer over emotes. Catalogs are cached and refreshed every 30 minutes while chat is active, not fetched per message. Unknown or unavailable images remain readable text. The info icon in the chat preview reports loaded counts and unavailable providers. Private/personal packs and animated effects are not supported.

To test your connection, turn on **Twitch test stream**, select **Stream** or **Both**, then click **Start** and confirm. It sends video to Twitch without making it viewable live. **Record** remains local even while this test setting is saved. Check connection stability and bitrate in [Twitch Inspector](https://inspector.twitch.tv/).

Turn test mode off when you want to go live. Starting a stream always asks for confirmation.

## Draw on your screen

Click **Annotate** or press **Control–Option–Command–D**. Press **Esc** to stop drawing. Click **Clear** to erase the drawing.

The compact icon toolbar uses native pen, marker, eraser, arrow, shape and edit symbols in a single row, without footer text. Hover for descriptions; blue outlines mark the selected tool and Straight mode.

In **Settings → Drawing**, choose smoothing and pen width (1–24 pt, default **6 pt**), plus independent colors: **Pen**, red by default, for pen, arrows, and shape outlines; **Highlighter**, yellow by default; and, once **Fill shapes** is on, a **Fill color** for ellipse/rectangle interiors. Fill supports opacity, starts from a translucent pen color, and is off by default. Settings apply to new strokes without recoloring existing ink. Freehand and straight Pen/Arrow use the same tablet-pressure width; straight strokes retain contact pressure on pen-up. Highlight and Erase use a broader tip. The smoothing slider runs from **Off** to **Strong**; more smoothing steadies shaky strokes but adds slight lag.

Choose **Arrow** for a freehand stroke with an arrowhead at its end. **Straight** toggles straight pen lines and arrows. **Settings → Drawing → Pen buttons → Straighten only while held** defaults on: the mapped Straighten button (middle by default) temporarily straightens before or during a stroke; release returns subsequent strokes to the toolbar mode. Saved preferences are preserved. Tap the secondary button to toggle Pen/Erase (from other tools, return to Pen); hold it for a quarter-second to open the radial menu. Clockwise from the top: **Colors, Pen, Arrow, Rectangle, Ellipse, Erase, Undo, Highlight**. Hover and release to choose; release in the center or press Escape to cancel. Colors opens a second radial palette: choose **Stroke / Highlighter / Fill**, then a swatch; Fill also offers **No fill**, and **‹ Tools** goes back. The toolbar palette button opens the same colors. **Settings → Drawing → Pen buttons** lets you learn and assign any delivered non-primary button. Drivers that consume a button for Scroll must first map it to a click that apps receive. Tablet Companion offers reversible global Wacom assignments; no application profile is created.

Tablet Companion’s suggested tablet-button order is **Annotate, Webcam punch-in, Stroke width, Clear**. These are the tablet’s ExpressKeys, not its pen buttons. Each available button can be reassigned; Color remains an option. Punch-in works outside drawing mode while StreamApp’s Desktop webcam is enabled. Color, width, and Clear shortcuts work only while drawing; Clear is not a pen action. Escape dismisses a picker before leaving drawing.

Drag **Ellipse** or **Rectangle** to create shapes. Hold **Shift** for circles/squares, or 15° angle snapping in Straight mode. **Erase** defaults to removing whole strokes, arrows, or shapes you touch. Choose **Settings → Drawing → Eraser → Just what you touch** to rub out just the area under the tip instead. **Undo** reverses the last drawing or eraser gesture, restoring all objects removed in that gesture.
